## 产品介绍

### 技术栈

- **渲染管线**：基于 Unity 的 HLSL Shader（ForwardBase + SRPDefaultUnlit），内置独立且完整的 **NovaToon 渲染框架**（包含 Toon Ramp、SDF 面部阴影、Rim、描边）。
- **物理光追核心**：在 Unity Editor 中通过 C# 手写 **NovaTriangleBVH**（SAH 分箱构建、AABB 遍历、Ray-Triangle 求交）。
- **离线烘焙（Avatar/细雪）**：16 方向光照图集烘焙，生成 4x4 的 RGBAHalf 阴影图集，运行时零计算，仅做图集采样，极大降低 Avatar 性能开销。
- **运行时计算（World/朔雪）**：基于 Compute Shader（`cs_5_0`）的实时 BVH 遍历，支持硬件级 VSSM（方差阴影）与 PCF 软阴影结合，防止面部死黑。
- **防死黑机制**：Avatar 版通过 Shader 内 `_IsFace` 开关直接原样输出面部 Albedo；World 版通过 VSSM 厚度检测与 bias 自适应机制解决阴影漏光与死黑。
- **动态熔断**：实时监控建树队列与显存溢出，压力过大自动降分辨率（1024 → 512），压力缓解后自动恢复，确保低端机不卡死。
- **资源管理**：全面使用 `NativeArray` 与 `Allocator.Temp`，杜绝 GC 压力；关闭软件/退出 Play 模式时强制释放所有 ComputeBuffer 与 RenderTexture。

### 架构概览

- **控制层**：通过自定义 EditorWindow（`Xixue_FluffBaker` / `NovaToon_ShadowBaker`）一键完成“BVH 构建 → 阴影烘焙 → 自动替换材质”。
- **数据层**：`NRTR_TriangleBVH` / `NovaTriangleBVH` 负责几何数据的加速结构构建；`PackedBVH` 负责将多模型的 BVH 压平为 GPU 可读的线性缓冲。
- **渲染层**：`Shuoxue_Shadow.shader` / `Xixue_ToonShadow.shader` 负责运行时采样；内置的 `NovaToon` 渲染管线负责最终的 Toon 着色。
- **防崩机制**：异步建树 + 5000ms 超时黑名单 + 动态熔断，确保大模型/低配机场景下不会卡死整个场景。

### 核心算法

- **SAH 分箱构建**：采用 12 分箱的表面积启发式算法，保证 BVH 树的质量，减少光线求交次数。
- **离线图集映射**：通过 `atan2(L_model.x, L_model.z)` 计算光照角度，直接映射到 16 个方向的图集 Tile，避免复杂的矩阵运算。
- **VSSM 方差阴影**：利用深度的一阶矩和二阶矩计算方差，结合切比雪夫不等式实现软阴影，并加入 `smoothstep` 防止漏光。
- **动态 Bias 适配**：根据 `NdotL` 的斜率动态调整 Bias，确保正面光照时不产生阴影痤疮（Acne）。

### 性能特征

- **Avatar（细雪）**：离线烘焙图集，运行时 0 计算，仅一次纹理采样，显存占用极低（单张 1024x1024 RGBAHalf 约 8MB）。
- **World（朔雪）**：GPU 实时 Compute Shader 路径，支持动态光源与复杂场景，压力过大自动降级至 512 分辨率。
- **适用场景**：VRChat Avatar（二次元模型）、静态 World 场景、需要高质量软阴影的展示环境。

### 已知限制

- **动态形变限制**：离线烘焙（细雪）针对静态姿势或轻微形变（如头发微动）效果最佳；如果 Avatar 发生剧烈骨骼形变（如大幅度跳舞），阴影可能出现错位或丢失。
- **多光源限制**：当前版本主要支持单方向光（平行光）的阴影烘焙，多光源场景需配合 NovaToon 的基础光照使用。
- **面部死黑**：Avatar 版通过 `_IsFace` 直接屏蔽面部阴影，确保绝不死黑，但这也意味着面部不会产生物理光追阴影（这是为了 VRChat 体验做出的妥协）。
- **平台限制**：离线烘焙在 Editor 中完成，支持 Windows / macOS；World 实时 Compute Shader 路径目前仅支持 PC 端，Quest 端仅支持 Avatar 离线图集方案。
